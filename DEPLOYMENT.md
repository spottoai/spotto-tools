# Setup & Usage

## AWS

See [AWS onboarding](onboarding/aws/README.md). `connect.sh` (Bash 3.2+) and
`Connect-SpottoAws.ps1` (PowerShell 7+) need only AWS CLI v2 and the customer's own
session, so they run in AWS CloudShell. Both require the Portal deployment binding and deploy the hosted CloudFormation templates
from `https://spotto-aws-onboarding.s3.amazonaws.com/cloudformation/`.

The templates in `onboarding/aws/cloudformation/` are generated by
`api/scripts/aws/generate-connect-templates.ts`. On push to `main`,
`.github/workflows/publish-aws-cloudformation.yml` publishes them to the
`spotto-aws-onboarding` bucket twice: `cloudformation/<file>` (latest) and the immutable
`cloudformation/v<TemplateVersion>/<file>`, which updates, the member StackSet and
Terraform pins use. It fails if a versioned file already exists with different content,
and fails closed on listing/download errors. The existence check lists each exact
key prefix with an exact-key filter, matching the publisher role's prefix-scoped
`ListBucket` permission; a longer matching key is not treated as the template.
Any template change must bump `TemplateVersion` (it signs in with GitHub OIDC as
`spotto-tools-template-publisher`, created by `iac/Aws_Onboarding_Infrastructure.ps1`). Rerunning the scripts updates customers' stacks;
`--repair` re-applies the role and `--check` reports version, drift and member status.
Publish all five templates before releasing the dependent API/UI/scripts/module.
The shared S3 publisher has no runtime customer authority. Provision regional SNS
with IaC, deploy the owning API and confirm subscriptions before customer launch.
API and AWS engine use one runtime principal per environment (production shared,
development separate); verify that credentials match each deployment's advertised trust. Public scripts never receive
Spotto's source credentials. CloudFormation access/storage stacks are regional;
only the definition-only billing stack runs in us-east-1, with billing files delivered to the selected deployment region.
The publisher rejects backward latest promotion and uses pinned official Actions.
Source tests/schema checks do not establish live AWS or strict processing residency.

## Prerequisites
- PowerShell 5.1 or PowerShell 7+
- Azure account with required permissions (see `README.md`)
- For detailed onboarding permission scopes, including optional `Log Analytics Reader`, see `onboarding/azure/README.md`

## Run onboarding script
```powershell
# Clone and enter the repo
# Run the setup script from onboarding folder
.\onboarding\azure\Setup-SpottoAzure.ps1
```

Follow the prompts to select tenant/subscriptions and capture generated credentials.
